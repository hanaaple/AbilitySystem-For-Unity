# HARNESS.md — 코드 작성 규약

코드를 **어떻게 짤지**에 대한 설계·실천 규약. 이름·포맷·멤버 순서 등 **스타일**은 [`../../project/CODE_CONVENTION.md`](../../project/CODE_CONVENTION.md).

> 이 폴더의 하위 문서(에디터 가이드 등)는 **이 규약을 상위로 두고** 따른다. 하위로 바로 점프하지 말고 이 문서를 먼저 본다.

---

## 설계 원칙

- 필요할 때만 범용화한다. 실제 유스케이스가 요구하는 범위만 구현한다.
- **공통화는 사용처 수로 크기를 정한다.** 사용처가 하나면 최소로. **이미 2+면** 작은 primitive만 뽑아 보일러플레이트를 남기지 말고, 생성·삽입·갱신·빈 상태까지 흡수한 상위 헬퍼를 처음부터 제안하고 차이만 콜백/파라미터로 노출한다.
- **좁은 스코프·가정 위에서만 성립하는 구현은 그 한정성을 스스로 표면화해 착수 전 확인한다.** 스코프 경계·되돌리기 비용 있는 데이터/구조 선택·동작 정책(우선순위·중복·기본값)이 갈리면 임의로 정하지 말고 유저에 확정받는다. **갈림이 겉으로 안 드러나도** 좁은 상황에서만 동작하게 짜고 있으면 그 가정을 먼저 밝힌다. 짜기 시작했어도 멈추고 묻는다.
- 범용 코드에 특정 사용처 정책을 심지 않는다. 범용 쪽은 결과를 인자로 받고, "무엇을"은 호출측이 정한다.
- **구조적 개념(컴포넌트·레이어·패턴)을 새로 도입할 땐 이름부터 붙이지 않는다.** 순서: ① 무엇인지(책임·구조·단위) 규정 → ② 기존 무엇이 이관/흡수되나 → ③ 어느 레이어에 속하며 그 레이어가 있나(없거나 유저가 일부러 안 만든 층이면 신설은 승인 대상 — 데이터 모델·레이어 변경) → ④ 소유권·데이터 모델 갈림 유저 확정 → ⑤ 구현. 이름부터 붙여 "만들었다"로 체크하면 그 라벨이 설계를 대신해 ①~④를 물을 기회가 사라진다. 스스로 묻는다: *"이건 무엇의 축소판이고, 기존 무엇이 여기로 와야 하며, 원래 어디 사는가?"* — 셋에 답 못 하면 아직 만들 단계가 아니다.

> 관련 상위 규약(중복 두지 않고 링크): 과설계 지양·"왜"의 품질 → [`../HARNESS.md`](../HARNESS.md) '프로젝트 핵심 원칙'.

## 연쇄 호출

- 다른 객체로 건너가며 파고드는 연쇄 호출 금지. 중간 결과를 지역 변수로 받아 한 단계씩 접근한다.
- LINQ·빌더처럼 한 대상을 이어서 조립·변환하는 fluent 체인은 허용한다. (줄바꿈은 CODE_CONVENTION '긴 줄' 참고.)

```csharp
// ❌ 다른 객체로 건너가며 파고드는 연쇄 호출
var ammo = player.GetGameObject().GetWeapon().GetAmmo();

// ✅ 한 단계씩 지역 변수로
var weapon = player.GetWeapon();
var ammo = weapon.GetAmmo();

// ✅ 허용 — 한 대상을 이어서 조립하는 fluent 체인(LINQ·빌더)
var expr = new GameplayTagQueryExpression().AnyTagsMatch().AddTags(tags);
```

## 주석

코드가 말하지 못하는 "왜"만 적는다. 없어도 되면 없앤다.

- 이름이 먼저. 주석은 이름이 담을 수 없는 "왜"에만.
- "왜"를 적고 "무엇"은 적지 않는다.
- 외부 포인터(`→D8`·본문 속 `(UE: FAggregator)`) 금지. 결정 근거·설계 이력은 `dev-docs/`에 둔다.
  - 예외 — UE 원본에 대응하는 함수는 XML 주석에 `/// <remarks>UE: 클래스::함수</remarks>` 한 줄로 대응 UE 함수를 적는다. 대응 관계만 적고, 근거·UE와의 차이는 `dev-docs/`에 둔다.
- 변하기 쉬운 값(임계값·경계)을 주석에 복제하지 않는다.
- "여길 바꾸면 저기도"인 상호 의존은 주석으로 명시한다.
- 동작 명세는 테스트로 고정한다.
- 공개 API는 XML 주석(`/// <summary>`).

```csharp
// ✅ 이유(왜)를 적음
// Rigidbody 이동은 FixedUpdate에서 처리해야 물리 스텝과 어긋나지 않음
private void FixedUpdate() { }

// ❌ 코드를 되뇜 (무엇)
// FixedUpdate 함수
private void FixedUpdate() { }

/// <summary> 플레이어에게 데미지를 준다. </summary>
/// <param name="damage">입힐 데미지 양</param>
public void TakeDamage(int damage) { }
```
