# git-harness — 에이전트 git 작업 규약

**에이전트가 커밋·push·PR·병합을 할 때 따른다.** 상위: [HARNESS.md](HARNESS.md). 커밋 형식·타입·PR 본문 등 공통 규약은 [dev/git-convention.md](../dev/git-convention.md).

---

## 커밋·push

- 커밋·push는 유저가 요청할 때만 한다.
- 훅 우회·서명 생략(`--no-verify` 등)은 유저가 명시 요청할 때만.
- 스테이징은 경로를 지정해서 한다. 유저 WIP가 섞였으면 push 전 `reset`/`restore --staged`로 뺀다. 내가 만들지 않은 변경은 커밋 전에 유저에게 묻는다.
- GitHub 작업은 `gh` CLI를 쓴다.

## 병합

- **병합은 유저가 병합을 명시할 때만 한다.** PR 생성·push 지시는 병합 지시가 아니다. "PR 확인해서 해"처럼 확인인지 병합인지 갈리는 말이면 한 줄로 되묻는다.
- **병합 전 확인** — [git-convention](../dev/git-convention.md) '병합'의 확인 항목을 보고 결과를 유저에게 알린 뒤 병합한다. 하나라도 걸리면 병합하지 않고 보고한다.
- **병합 뒤 원격 브랜치 삭제**는 되돌리기 어려우니 병합 보고 때 "브랜치 지울까요?"로 확인받고 지운다. 저장소 설정의 자동 삭제를 켤지는 유저 판단(지금 꺼짐).
- **병합 뒤 로컬 갱신** — 로컬에 미커밋 변경이 있으면 갱신 전에 유저에게 알리고, 이름 붙인 stash로 감쌌다 다시 적용한 뒤 파일 목록·내용·스테이징을 갱신 전과 대조한다. stash는 유저 확인 전엔 지우지 않는다. 미추적 파일은 stash에 넣지 않는다(`-u`는 autocrlf로 LF→CRLF).
